# Guia de evidências

As capturas devem mostrar o desenvolvimento real do projeto e ser organizadas para a montagem do PDF final. Sempre que possível, a captura deve incluir o comando ou a ação realizada e seu resultado legível. Não expor senhas, tokens, credenciais, dados pessoais reais ou outros segredos.

## Evidências a guardar

- Preparação do ambiente e da estrutura inicial do projeto.
- Inicialização e uso do controle de versionamento.
- Criação de branches, commits e histórico relevante.
- Abertura, revisão e conclusão de pull requests pelos integrantes.
- Ciclo TDD: teste falhando (Red), implementação mínima com teste passando (Green) e refatoração mantendo os testes aprovados (Refactor).
- Execução da análise estática e seu resultado.
- Execução da formatação e seu resultado.
- Execução do workflow no GitHub Actions, incluindo o resultado das verificações automatizadas.
- Testes unitários do backend e do frontend.
- Testes de integração entre API e armazenamento, usando dados de teste separados.
- Integração entre frontend e backend.
- Aplicação funcionando nos fluxos de cadastro, consulta, edição e exclusão.
- Cálculo da idade funcionando a partir da data de nascimento.
- Construção da imagem Docker e execução do contêiner.

## Momentos dos prints

Os prints serão feitos durante o desenvolvimento real. Antes dos principais resultados, será indicado um **PONTO DE PRINT** com o que deve aparecer na captura e o local sugerido para armazená-la.

## Cuidados

- Tirar capturas durante cada etapa; não tentar recriar evidências apenas no final.
- Identificar a etapa e, quando útil, a data de cada captura.
- Manter os textos e resultados legíveis.
- Usar somente dados fictícios nos testes e nas demonstrações.
- Revisar todas as imagens antes de incluí-las no PDF.
